# 2026-11-23 Progress

## Bot Update #23 — Slip OCR transaction-ref extraction fixed (per-wallet layouts)

**Incident (2026-11-23 ~08:29–08:36):** slip #202608 (@OK8763, 1,000 Ks KBZ) was recorded with extracted_tx_id "202608" — the year+hour of the receipt's "23/11/2026 08:29" fused together after space cleanup — because the date/time line sat next to the လုပ်ဆောင်မှုအမှတ် label and `extract_transaction_last6` returned the first keyword-adjacent digit run before ever reaching the KBZ `010…` pattern check. The duplicate-slip check therefore ran against a number that was never a reference. The slip-watch agent's first pass (08:31) correctly refused and alerted; a second pass (08:36) approved on the remaining checks. The owner verified by hand that the real Transaction No (…897249) was unused, so the approval stands.

**Owner's input:** sample receipts for every wallet — KBZ (Burmese + English E-Receipt), Wave Pay, AYA Pay, UAB Pay — with the instruction to teach the reader to read them accurately.

**Fix (`bot_app/services/ocr.py`, `extract_transaction_last6` rewritten):**
1. **Date/time masking first** (`_mask_dates_times`): `DD/MM/YYYY`, `YYYY/MM/DD`, `HH:MM[:SS]`, and month-name dates ("12 Nov 2026", "09 November 2026", "26 September 2026") are blanked before extraction, so their digits can never fuse into a fake ref. Bare digit runs are untouched — UAB's date-prefixed ref `121120266442341` survives whole.
2. **KBZ `010…` refs first**: the `010\d{12,20}` pattern (15–23 digits) is searched on the space-stripped masked text BEFORE the keyword pass — nothing else on a receipt looks like it, and a ref split by an OCR space still hits.
3. **Keyword candidates scored**: digit runs after a tx label (same line, position-aware as before) and on the line after a label line are all collected on the masked text; phone-like and date-like runs are filtered; the longest plausible run wins (real refs: Wave 10, AYA 12, UAB 15, KBZ 20 digits). The old first-hit behaviour is gone.
4. Fallback unchanged in spirit (first 8–15-digit run that is not a phone/date), now on masked text.

**Tests:** 7 new tests in `tests/test_ocr.py` built from the owner's samples — KBZ Burmese receipt (→153538), KBZ English receipt (→753480), the #202608 regression layout with the datetime beside the label and the ref split by a space (→897249), the datetime-alone trap (→None), UAB (→442341), AYA (→910725), Wave (→680460). Full suite: **546 passed / 1 known pre-existing failure** (`test_user_api_bootstrap_new_user`).

Bot-side only — no app update. Return contract unchanged (last 6 digits), so slip IDs, the duplicate check and `extract_slip_facts` / `extract_amount_and_tx_from_bytes` all benefit without call-site changes.
