# 2026-11-22 Progress

## Bot Update #20 — Slip amount auto-fill from OCR (pushed 2026-11-22 on the owner's instruction)

**#20.1 (added the same night, owner-approved):** the native-app and Mini App flows generated the Top-Up ID as a random 8-character string (the owner spotted `E1EACVR1` on the 2026-11-21 midday O Mar' Dee Dee slip and asked why it was not read from the receipt). Both flows now prefer the bot flow's transaction-derived ID (`#` + tx last-6) when OCR read a reference, falling back to the random ID when unreadable or already taken (a record is never overwritten). The app flow also records `extracted_tx_id` now, so the agent duplicate check covers app slips.

**Problem (owner-reported 2026-11-22 ~00:06):** many customers select the wrong top-up amount before uploading their slip (e.g. select 1,000 Ks, send a 5,000 Ks slip); the recorded slip amount was the *selected* one, so mismatches landed on the admin/owner to untangle (e.g. the 2026-11-21 O Mar' Dee Dee 500-vs-4,000 duplicate submissions).

**Fix:** at slip intake, the slip photo's OCR text is mined for the transfer amount; when one is confidently read it replaces the customer-selected amount on the recorded slip.

- `bot_app/services/ocr.py`
  - `extract_slip_amount(ocr_text)` — label-anchored first (amount labels EN/MM, value on the same or next line; "balance" lines never count), then currency-anchored (numbers next to Ks/MMK/ကျပ်, most-repeated wins). Token filter rejects dates, times, phone numbers and transaction references (comma/decimal/round + 100–1,000,000 Ks range).
  - `parse_slip_ocr_bytes(img_bytes)` — OCR.space base64 variant for flows that receive raw bytes.
  - `extract_slip_facts(file_path)` — ONE OCR pass returning `(order_id, tx_last6, amount)`; `extract_order_id_and_tx` now delegates to it (same signature/behaviour).
  - `extract_amount_and_tx_from_bytes(img_bytes)` — `(tx_last6, amount)` for byte-based flows.
  - `resolve_slip_amount(selected, detected)` — detected wins when ≥ 500 Ks; below that (or None) the selection stands and the slip is flagged for the admin.
- Intake wiring (all three channels): `bot_app/handlers/topup.py` (Telegram bot), `bot_app/routes_app.py` `POST /api/app/topup` (native app — also now records `extracted_tx_id`, previously always empty), `bot_app/routes_user.py` `POST /api/user/topup-slip` (Mini App).
  - Admin alert shows a 🤖 correction line when the amounts differ (selected → slip amount) or a ⚠️ "OCR could not read the amount" flag when it falls back; the Approve button, recorded amount and customer confirmation all use the final amount; the customer is told when their amount was corrected.
- `bot_app/services/slips.py` — `record_slip` accepts `ocr_amount` / `selected_amount` (stored on the record for audit); `pending_slips_for_agent()` exposes both so the slip auto-review agent can see them.
