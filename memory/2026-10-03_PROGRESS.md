# 2026-10-03 — Progress Log

## Milestone 2: Modal scroll-lock no longer hides the sticky navbar

**Bug report:** opening Purchase Detail after scrolling down made the top header bar and
the sidebar's top vanish (fine when opened from the unscrolled top of the list).

**Root cause:** Naive UI's NModal body scroll-lock sets `overflow: hidden` on `<body>`;
a `position: sticky` ancestor chain under a hidden-overflow body stops sticking, so the
sticky header (and sidebar) scrolled out of view exactly when the page was scrolled.

**Fix:** `:block-scroll="false"` on every NModal (12 across SlipsView ×2, RedeemsView ×3,
CustomersView, KeysView ×3, CustomerDetailView ×2, PurchasesView). Background stays
scrollable while a modal is open — the minor trade-off vs keeping the navbar alive.
Verified in-browser: scrolled, opened a detail row → header top stays 0, sidebar stays at
its sticky offset, modal renders normally. Build clean; 381 tests passing.

## Milestone 1: Option A — Vercel Fluid usage cut (branch `perf/option-a-vercel-budget`)

**Ask:** usage charts showed Fluid Provisioned Memory at 225.3/360 GB-Hrs (63%) and Fluid
Active CPU at 1h58m/4h (49%) — projected to hit limits within ~1 week as active users grew
from ~12 to 150+ after the Points launch. Root cause identified: the dashboard's SSE stream
(`/api/admin/events`) holds a function instance open in 60s cycles for as long as any
dashboard tab is open (`maxDuration: 60` + 20s heartbeat) — 1.766 GB × open-hours per day.
Bot-driven writes never reached the SSE in-process bus on Vercel anyway (separate process) —
the dashboard already relied on the version-poll for those.

### Changes (all in this milestone)
1. `dashboard/src/api.ts` — `openVersionStream` gated by `sseEnabled`
   (`import.meta.env.DEV || VITE_SSE_ENABLED === '1'`). Production builds skip SSE entirely
   and synchronously signal `onState(false)` so App.vue starts its poll fallback; dev keeps
   true push. Zero retry traffic (no wasted ticket POSTs).
2. `dashboard/src/App.vue` — version-poll interval 15s → **30s**, tunable at build time via
   `VITE_VERSION_POLL_INTERVAL_MS`; block comment rewritten to match the new dev/poll split.
3. `dashboard/src/components/layout/AppHeader.vue` — poll tooltip text "every 15s" → "every 30s".
4. `bot_app/routes_admin.py` — `LIVE_SYNC_MIN_INTERVAL` 30s → **120s** (keys live-sync probe).
5. `bot_app/services/admin_telemetry.py` — `SERVER_TELEMETRY_TTL` 30s → **120s** (overview
   server probes; stale-while-revalidate still returns instantly, refresh just runs 4× less).
6. `vercel.json` — `api/index.py` **memory 1024** (from the 1766 MB Python default): every
   remaining invocation bills ~42% fewer GB-seconds; TeleBot+Flask fits comfortably.

### Expected effect
Monthly GB-Hrs from ~225 (63% of budget) down to roughly **~50–80** (~15–20%) — webhook
processing is the remaining consumer. Render/VM split (Option C) postponed until CPU
(4h/limit, the tighter ceiling long-term) actually approaches the limit with user growth.
