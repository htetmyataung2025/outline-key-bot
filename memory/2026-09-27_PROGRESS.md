## 🐛 Critical: Upstash redis_set silently lost every write containing '/' (fixed, pushed)

**Found while verifying the Telegram-sync feature locally**: dashboard approve
succeeded but the admin message wasn't edited. The slip had been recorded by
old code (pre-restart), and re-testing then exposed a deeper bug.

**Root cause** ([bot_app/storage/kv.py](file:///home/zixuan/Projects/outline-key-bot/bot_app/storage/kv.py)):
`redis_set` sent the JSON value as a GET path segment via
`urllib.parse.quote(json.dumps(value))` — but quote's default `safe='/'`
leaves forward slashes intact, so any state blob containing a `/` (file_ids,
captions, URLs…) made Upstash reject the command with `ERR syntax error`
(HTTP 400). The `except`/status check swallowed it → **Upstash writes failed
silently while the /tmp file copy succeeded**, so prod (no writable /tmp
across instances) and the local server diverged without anyone noticing.

**Fix**: POST the value as the request body — `POST /set/<json-quoted-key>`
with `Content-Type: text/plain` (verified against the real Upstash instance
with tricky payloads: `/`, `+`, `=`, `#`, unicode). Regression tests in
[tests/test_kv_storage.py](file:///home/zixuan/Projects/outline-key-bot/tests/test_kv_storage.py)
(2 tests: value travels in body not URL; failure status propagates).

**E2E verified locally** (dev bot, real Telegram): slip recorded with
admin_messages → dashboard review → `editMessageCaption` landed
"✅ APPROVED (+12,345 MMK)" + button removed (confirmed via the
"message is not modified" response on re-edit). Test artifacts cleaned.

**Suite**: 168/168 (includes the parallel WIP's tests), pyflakes clean.

**Next**: confirm Vercel deploy picked this up (`/diag` git_sha); the same
silent-write-loss may have been affecting prod state sync since session
pooling landed — worth watching the dashboard after deploy.

## 🚦 Login rate-limit implemented (commit pending, NOT yet pushed)

**User request**: implement the recommended `/login` brute-force protection (the "next" item from the status review).

**Design**: per-client-IP fixed-window counter on `POST /api/admin/login`. EVERY attempt counts; a **successful login clears the counter**, so the limit effectively measures *consecutive* failures — the admin mistyping twice a day never feels it, while an attacker gets 5 attempts then a 429 (with `Retry-After`) before the password is even compared. Defaults: **5 attempts / 10 min**, tunable via `LOGIN_RATE_LIMIT_MAX` / `LOGIN_RATE_LIMIT_WINDOW` (read at call time, like the admin IDs).

- [bot_app/storage/kv.py](file:///home/zixuan/Projects/outline-key-bot/bot_app/storage/kv.py): new `redis_increment_with_expiry(key, ttl)` (POST `/incr/<key>` then `/expire/<key>/<ttl>` — TTL refreshed every increment so the window measures "since the last attempt" and a crash between the two calls can never leave a TTL-less key = permanent lockout) and `redis_delete(key)`. Deliberately bypasses `redis_set` so counters never bump the dashboard data-version / SSE stream.
- [bot_app/helpers/rate_limit.py](file:///home/zixuan/Projects/outline-key-bot/bot_app/helpers/rate_limit.py) (new): bucket key = `login_rl:<sha256(ip)[:32]>` (raw IPs never in the KV namespace); Upstash when configured, thread-safe in-memory fallback for local dev/tests; `client_ip_from_headers()` prefers Vercel's `X-Vercel-Forwarded-For`, then the **rightmost** `X-Forwarded-For` entry (client-supplied leftmost values are spoofable — never trusted), then `X-Real-IP`, else `"unknown"`.
- [bot_app/routes_admin.py](file:///home/zixuan/Projects/outline-key-bot/bot_app/routes_admin.py): `/login` registers the attempt before validating; over-limit → **429** + `Retry-After` + English error; 400 missing-fields returns before counting; success clears the bucket.
- [dashboard/src/App.vue](file:///home/zixuan/Projects/outline-key-bot/dashboard/src/App.vue): 429 → Burmese message ("Login ကြိုးစားမှု များပြားနေပါသည်…").

**Tests**: 11 new — [test_admin_login_ratelimit.py](file:///home/zixuan/Projects/outline-key-bot/tests/test_admin_login_ratelimit.py) (block after max even with correct password + `Retry-After`, success resets the budget, per-IP isolation, 400s don't count, non-admin-ID attempts count, `LOGIN_RATE_LIMIT_MAX` env tunable, trusted-IP header priority incl. spoof rejection) and 4 in [test_kv_storage.py](file:///home/zixuan/Projects/outline-key-bot/tests/test_kv_storage.py) (incr+TTL-refresh call sequence, unreachable→None, unconfigured→None/False, DEL command path). New autouse conftest fixture `reset_login_rate_limits` wipes the in-memory store around every test so counters never leak between tests. Suite **204/204**, pyflakes clean, `npm run build` clean.

**Caveat surfaced**: IP keying on Vercel uses edge-appended headers, so an attacker rotating real IPs could spread attempts — the admin ID check + long secret remain the main line; a global counter was rejected because it would let anyone DoS the admin's own login.
