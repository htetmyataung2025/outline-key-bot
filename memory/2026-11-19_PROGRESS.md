## Bot update #7.2 — deleted keys still visible: probe alignment + /keyprobe diagnostic

## Bot update #7.3 — port identity was too weak: Outline recycles freed ports
The owner ran /keyprobe (worked exactly as designed): both servers reachable (101 + 64 live keys), and all 11 of the owner's records matched live keys **via port only** — including the deleted ones. Root cause: when a key is deleted, Outline can hand its freed port to a later-created key, so "(host, port) is live" does NOT prove the record's key is alive. Fix in `routes_user.py`: `_record_liveness()` now indexes live keys as objects and a port match only counts when backed by the key name (name minus its trailing expiry date — renewals rewrite only the date); a same-server name match is also an identity of its own ("name"). A port held by a differently-named key is reported as a conflict. `diagnose_user_keys()` now also returns the record's key name, the live holder's name/id and the conflict flag (and its plan field is fixed to `plan_name` — the /keyprobe report previously printed blank plan names). `/keyprobe` renders the conflict explicitly ("အဲ့ Port ကို တခြား key သုံးနေပြီ") and shows the live key's name for alive verdicts.
Tests: +2 (recycled-port record hidden while name-matched key kept; diagnose flags the conflict with the holder's name). Full suite: **447 passed / 1 failed** (known pre-existing). Pushed via the GitHub connector. Next: owner re-runs /keyprobe — the 3 deleted keys should now grade 🗑 (with port-conflict notes if their ports were recycled); Mini App My Keys should drop them on next open.
