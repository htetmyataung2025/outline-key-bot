## Bot update #6 — reliable broadcast + app notifications
Problem: the admin broadcast sent to every user in one synchronous webhook-request loop (no pacing, all errors swallowed). Vercel's 60 s function wall killed it mid-loop as the user list grew — most customers silently never received broadcasts and the admin got no completion report.

Fix — new `bot_app/services/broadcast.py` (resumable Redis job):
- `start_broadcast()` snapshots recipients (all users minus admins, deduped) into a `broadcast_job` record; a second start while one is running is refused with progress.
- `advance_broadcast()` sends a bounded chunk (cap 120 sends / 40 s budget, 0.05 s pacing), honours Telegram 429 `retry_after` with one retry, counts blocked/deactivated separately, persists the cursor every 10 sends. Completion sends the admin a summary (Telegram reached / app pushed / blocked / failed) + audit log, exactly once.
- Continuation drivers: the admin's own request (first chunk), a "▶️ ဆက်ပို့ရန်" inline button (`broadcast_continue` callback in `handlers/admin.py`), and the existing ~15-min `/reminder-check` pinger (hook added in `routes.py`) — so a broadcast always finishes even if the admin walks away.
- App fan-out: every processed recipient also gets the announcement via `services/app_notify.push_app_notification` (type `broadcast`, HTML stripped to plain text; photo broadcasts use the caption or a fallback line). The current app build already raises a phone notification for unread inbox items (NotifCheckWorker) — no app release needed. Blocked-the-bot users still get it in the app.

Wiring: `handlers/menu.py` (text) and `handlers/topup.py` (photo) broadcast blocks now create + advance the job and post progress; `tests/test_admin_action_audits.py` broadcast test retargeted its `load_all_users` stub to the service (assertions unchanged).

Tests: new `tests/test_broadcast.py` (8 tests). Full suite: **426 passed / 1 failed** — the only failure is the known pre-existing `test_user_api_bootstrap_new_user`.

Status: prepared + staged for the user to push via GitHub web (no git credentials in the assistant VM). After deploy, verification = admin sends a test broadcast and receives the completion summary with counts.

## Bot update #7.1 — hotfix: admin purchases actually unlimited + stronger deleted-key pruning
Owner tested #7 in the Mini App and reported both fixes incomplete:
1. **"Unlimited" was display-only.** The wallet card showed Unlimited, but the purchase dialog still read the raw stored balance (0 Ks) and demanded a top-up. Root cause: the Telegram bot's unlimited-admin behaviour comes from `billing.get_user_balance()` returning a 999999999 sentinel for admins; the Mini App was built on `get_user_balance_breakdown()` (raw stored wallet) and never got that logic. Fix: `POST /api/user/purchase` no longer charges admins at all (no deduction, no refund path; balance check was already admin-skipped), and the Mini App treats `wallet.unlimited` as always-sufficient — purchase dialog gate, checkout summary line, fallback badge and the Shop header balance all render "Unlimited" for admins (`AppDialogs.vue`, `views/ShopView.vue`).
2. **Deleted keys still showed** (Overview snapshot still counted 3 after the #7 deploy). The id-only identity check was too fragile — a record whose key_id cannot be resolved (registry miss / URL drift) failed open forever. Fix: bootstrap now fetches live key objects via new `outline.get_live_keys_by_server()` (same probe/cache; `get_live_key_ids_by_server` derives from it) and drops a record only when its own server answered AND none of three identities match a live key: key id, cleaned access-URL base, or (host, port) — Outline keys are unique per port, so the port identity survives URL re-encoding/fragment drift (`_ss_host_port()` in `routes_user.py`). Still fail-open when the record's server did not answer.

Tests: +3 (admin purchase never charged — asserts the stored breakdown stays 0; port-identity pruning without a registry entry; raw live-keys list). Full suite: **438 passed / 1 failed** (known pre-existing `test_user_api_bootstrap_new_user`). Mini App `npm run build` passes.
