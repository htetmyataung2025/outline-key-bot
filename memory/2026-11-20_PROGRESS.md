# 2026-11-20 Progress

## Bot update #12 — Support replies leave the app inbox (owner decision)
- **Problem**: every Support Chat reply (admin + Muse agent) was pushed into the app notification inbox via `push_app_notification(..., "support", ...)`. The inbox is capped at 30 items, so chat back-and-forth would fill it and push out real announcements (broadcasts, top-up approvals, expiry warnings).
- **Change** (`bot_app/services/support_chat.py`): `admin_reply()` and `agent_reply()` no longer push to the inbox; replies live only in the support thread. The now-unused `app_notify` import was removed. Telegram-side behaviour unchanged (forwards, Reply routing, presence, oversight copies, escalation alerts).
- **App side** (H&E VPN, same v0.6.8 fix-round): `InboxNotifier` now detects new support replies straight from `GET /api/app/support/messages` (seen/notified timestamps in prefs, baseline on first check, one fixed notification id) and posts the phone notification itself; opening Support Chat marks replies seen and dismisses it.
- **Tests** (`tests/test_support_chat.py`): fixture keeps a `push_app_notification` tripwire stub (`raising=False`); admin/agent reply tests now assert `store.pushes == []`. Suite: **476 passed / 1 known pre-existing failure** (`test_user_api_bootstrap_new_user`).
