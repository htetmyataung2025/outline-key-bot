## Session 2: Local dev-bot freeze — force-join opt-out + settings-recursion fix

### Symptoms (local `--mode hybrid` on the Dev bot)
1. Console spam: `Force Join Check Error: ... 400 Bad Request: chat_id is empty`.
2. `/start` got no reply at all; Telegram showed `pending_update_count=1`
   stuck for 30+ min while Flask kept serving.

### Root causes
- `.env` had `REQUIRED_CHANNEL=` (set-but-empty) → `os.environ.get` default
  never applied → `get_chat_member("")` failed on every non-admin message.
- **The real freeze**: `_get_default_settings()` built defaults via the
  dynamic views `list(MY_PAYMENT_PHONES)` / `dict(PLANS)`, whose `_phones()` /
  `_data()` call `get_system_settings()` again *before the cache is set* →
  mutual recursion. `RecursionError` was swallowed by `except Exception: pass`
  and every unwind level did a KV round-trip (~0.3 s × ~300 levels) → one cold
  `get_system_settings()` ≈ minutes, freezing the inline (/start) handler.
  Diagnosed live via a new `kill -USR1` faulthandler stack dump in hybrid mode.

### Fixes
- [bot_app/config.py](file:///home/zixuan/Projects/outline-key-bot/bot_app/config.py)
  — `REQUIRED_CHANNEL` now `None` when the env value is blank (Option B:
  force-join disabled for local dev; unset still defaults to `@hefeature`);
  new pure helpers `env_payment_phones()` and `default_plans()`.
- [bot_app/utils.py](file:///home/zixuan/Projects/outline-key-bot/bot_app/utils.py)
  — `is_user_subscribed()` short-circuits `True` when `REQUIRED_CHANNEL` is
  `None` (no Telegram call at all).
- [bot_app/services/settings.py](file:///home/zixuan/Projects/outline-key-bot/bot_app/services/settings.py)
  — `_get_default_settings()` builds from env/constants only; comment records
  the recursion hazard.
- [index.py](file:///home/zixuan/Projects/outline-key-bot/index.py) — hybrid
  runner: polling thread supervised (restarts + loud traceback if it ever
  exits) and `SIGUSR1` dumps all thread stacks for future freeze diagnosis.

### Tests
